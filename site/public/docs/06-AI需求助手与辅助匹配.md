# AI 需求助手与辅助匹配 · V0.2

更新时间：2026-10-27。面向大众的技能与经验互助平台，以同校场景作为首轮验证；本次仍使用虚构校园和人物。

## 1. 问题与目标

用户通常先有具体困惑，未必能选对技能标签或把帮助范围说清楚。例如“照片总是乱”需要进一步区分构图、后期和器材问题。固定标签只能判断大方向，难以解释供给的具体经历是否适合当前目标。

本次新增两项能力：通过多轮对话整理需求；在规则筛选后的候选中，结合具体目标、服务范围与经历辅助推荐。产品目标是降低表达门槛、让推荐理由可核对。当前没有用户访谈、转化提升或真实模型效果数据。

## 2. 用户流程

1. 从首页或导航进入“AI 需求助手”。
2. 说出具体困惑，助手追问基础、目标、形式、时间和单次/持续意愿。
3. 生成可编辑需求卡；缺失内容显示待补充，模型不得默认时间和意愿。
4. 用户可先预览匹配，再主动确认发布。对话本身不发布、不创建预约。
5. 展示候选、推荐理由、资料引用与待确认事项；先查看经历或聊天。
6. 已发布需求进入原有两人/三人互助环搜索与单向自愿帮助流程，后续确认和结算沿用业务规则。

示例：
- 用户：“会按 C、G、Am、F，但换和弦总是停顿。”
- 助手：整理目标，追问形式、时间与是否持续。
- 用户：“线上，周六下午，先试一次。”
- 用户核对卡片后发布；候选说明其服务范围包含基础和弦转换，同时提醒需确认具体安排。

## 3. 功能与边界

| 功能 | 当前实现 |
| --- | --- |
| 需求对话 | 服务端 DeepSeek 对话接口、结构化需求、最多保留最近12条消息作为单次输入；真实调用待配置 |
| 可编辑需求卡 | 技能、标题、具体目标、基础、线上/线下、演示时间段、持续意愿；明确确认发布 |
| 匹配 | 先检查同校、技能标签、时间、形式、接受资格、条目开放状态和已有预约，再请求模型排序解释 |
| 可核对依据 | 推荐只能引用当前候选；引用必须是候选标题、范围或经历中的连续原文，未知ID或不存在引用被过滤 |
| 交互示例 | 三个预设故事和固定模板解释；界面明确标注不调用模型 |
| 异常处理 | 未配置、内测码错误、超时、服务繁忙、输出截断/损坏、引用无效、没有候选均有明确反馈 |
| 隐私 | 对话只在本次页面会话内；发布的需求保存在当前浏览器；真实模式告知会发送对话和候选资料至 DeepSeek |

模型仅辅助判断，不能认定经历真实性、伪造评价、承诺匹配成功、替用户同意或修改帮助次数。引用真实存在只证明“有这段资料”，不证明模型的推断一定正确。多人环仍由规则搜索生成，本版没有用模型自主规划或执行整个互助环。

本版仅支持原有五类技能，另有“其他需求”；“其他需求”会正常保留，但不假装有对应供给。只有周六/周日下午两个演示时间段，其他时间需要澄清或手动调整。尚无向量检索、跨标签召回、跨校线上互助或生产级日历。

## 4. 模型接入与架构

浏览器 → 同源 `/api/ai` → DeepSeek Chat Completions → JSON 结构与引用校验 → 返回草稿或推荐。

- 前端源代码位于 `site/public/`；原先 `site/dist/` 改为构建产物。
- Vinext/Cloudflare Worker 提供服务端接口，保留原有品牌、业务逻辑与公开访问。
- 模型端点固定为 DeepSeek 官方接口，前端不能指定端点、模型或系统提示。
- 默认模型为 `deepseek-flash`，可通过服务端 `DEEPSEEK_MODEL` 变更。
- 使用 JSON 输出、关闭思考模式、最多1600输出token、25秒请求超时，无自动付费重试。
- 无候选时直接返回，不调用模型。
- 测试使用模拟的外部接口响应，不会产生模型费用。

接口对照官方文档（2026-10-27 核对）：
- Chat Completions：https://api-docs.deepseek.com/api/create-chat-completion/
- JSON Output：https://api-docs.deepseek.com/guides/json_mode/

## 5. 密钥与公开体验

当前站点尚未配置模型服务。用户已选择 DeepSeek，但尚未开通 API，不能将目前版本描述为“已完成真实模型联调”。

真实内测需要在托管站点配置：
- `DEEPSEEK_API_KEY`：密钥，只在服务端读取。
- `AI_ACCESS_CODE`：单独的内测码，通过页面口令框输入，不能使用 API Key 作为内测码。
- `DEEPSEEK_MODEL`：非敏感模型名称，默认 `deepseek-flash`。

密钥不得写入浏览器代码、GitHub、聊天或截图。本地开发放在被忽略的 `.dev.vars`；托管部署通过站点环境变量工具配置为秘密值。`site/.env.example` 只列变量名。

真实调用需同源请求与正确内测码；请求体限制24KB，对话单条1200字符、最多12条，候选最多12个。本版另有每个 Worker isolate 每分钟10次的尽力限流。它不是跨实例的可靠费用上限；大规模开放前需持久化配额、实名账号/授权、日预算及模型平台侧费用控制。平台供需仍来自客户端演示状态，生产版必须服务端重新检索和验证。

## 6. 评测设计

### 已执行的工程验证

`npm test`：29项通过，包括原有12项核心规则测试与新增17项需求、候选、接口测试。新增测试覆盖缺失字段、时间/形式不符、跨校/暂停/自己、资格限制、编辑后候选失效、不存在技能、候选ID与引用校验、密钥不返回、未配置、鉴权、请求尺寸、角色注入、截断/错误输出、超时和无候选不调用。

浏览器已走通：示例选择 → 澄清补齐 → 预览候选及资料引用 → 确认发布 → 进入互助环；真实模型效果尚未执行。

### 真实模型评测（待密钥配置后执行）

`site/evals/cases.json` 包含10个人工设计的合成样例，非真实用户数据。覆盖明确需求、表达模糊、信息缺失、时间不可用、多轮纠正、提示注入及候选范围差异。`npm run eval:ai` 默认拒绝调用；显式设置 `RUN_LIVE_AI_EVAL=1`，并在环境中提供测试密钥和内测码才运行。记录实际模型名、时间、延迟、字段检查结果，报告默认写到被忽略的 outputs 目录。

| 维度 | 检查方法 | 第一轮目标，尚非结果 |
| --- | --- | --- |
| 需求提取 | 对人工标注字段逐项比较；缺失值保持为空 | 标注字段准确率≥90% |
| 澄清质量 | 人工检查是否询问缺失信息、避免重复追问 | 大部分样例可在2轮内补齐 |
| 推荐适合度 | 人工标注强/可能/不适合；比较前3个候选 | 先报告样例与分歧，不在小样本上宣称统计提升 |
| 事实依据 | 候选ID存在、引用可核对；人工检查解释是否越过证据 | 伪造候选和资料引用0次 |
| 规则遵守 | 无资格、时间冲突、暂停和不适合均不可自动预约 | 硬规则绕过0次 |
| 性能与成本 | 真实请求延迟、错误率与模型控制台费用 | 测量后设定预算和响应目标 |

结构化字段自动检查不等于完整语义评测，提示注入测试也不证明模型一定安全。需要人工复核自然语言回复、目标是否被擅自补全以及解释是否误导。先跑合成样例，再在明确告知的数据使用范围内做小规模试用。
